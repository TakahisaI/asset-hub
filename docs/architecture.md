# データと操作の契約

管理画面とCLIは `server/operations.ts` の保存処理を共用する。UIの有無で登録できる内容や競合処理を変えない。CLIはJSONを標準出力、機械可読のエラーを標準エラー、失敗を終了コード1で返す。JSON Schemaは `assetctl schema` から取得する。

## コードとライブラリ

`src/`、`server/`、`tools/`、`tests/` は管理システムのコード。プロジェクト名・コレクション・個別モデルの説明・生成条件は `ASSET_HUB_ROOT` のデータに置く。コレクションは任意の文字列の集合で、0個以上の利用先を関連付ける。資産の所有階層ではない。

| データ | 識別・保存 |
|---|---|
| アセット | 永続ID。`catalog/assets/<id>.json` は編集可能な現在の台帳 |
| GLB | 内容SHA-256。`.store/<hash>.glb` と `catalog/revisions/<id>/<hash>.json` |
| 動作設定 | 対象ID・GLB版を含むJSONのSHA-256。`catalog/behaviors/<hash>.json` |
| 出典・生成条件 | 元リポジトリの固定コミット、生成器、入力条件。`catalog/recipes/` |
| メモ | GLB版、任意の動作設定ハッシュ・プリセット・再生時刻・視点 |

台帳更新とファイル更新は別操作。`add` は登録済みIDを拒否し、`replace` は新版を追加する。名前・タグ・利用先・メモは新版でも保持する。固定版は上書きしない。Web/CLIの書き込みは同じファイルロックを取得し、置換・編集は `updatedAt` を照合する。タグ・利用先の追加削除はロック内の現在値に適用する。異常終了で残ったロックは自動で奪わずエラーにする。

## 物と動き

埋め込みクリップはGLBと一体。個別選択、時刻指定、速度、単発／ループを提供する。全クリップの同時再生はしない。

動作設定のプリセットは、クリップ一つと連続回転・照明を組み合わせる。ノード番号は対象GLB版の中だけで有効。回転軸はノードのローカル座標、角速度はrpm、点光源・スポット光源はglTFと同じ向き（スポットはローカル−Z）で指定する。弱風・強風、点灯・消灯などの名前や値はデータで定義する。これは決めた条件の再生であり、水流・風・布・接触の物理計算ではない。

モーションも永続IDを持つGLBアセットとして登録できる。モデル側の動作設定が使用するモーションのID・GLB版・クリップ番号を指定する。人型という分類だけで互換としない。共有するノードの基準姿勢・寸法・階層を照合し、名前が曖昧なときは明示的なノード対応を使う。体格・軸・骨格が異なる場合は制作側でリターゲットして対象モデル用の版を登録する。モーフの異なるモデルへの転用は拒否する。

人のモデルごとの使える動きは各モデルのプリセットで選ぶ。手続き的・物理的な動きは、固定コミットと入力・刻み幅を記録してクリップへ焼き付けられる。焼き付けた再生は元の物理コントローラ自体の移植を意味しない。

## 更新・配布の境界

動作設定を変えてもGLBのSHA-256は変えない。動作設定には独立したハッシュを付け、古い設定とメモを残す。GLBを更新して設定の対象版が古くなった場合、画面で知らせて適用を止める。参照する外部モーションの最新版への自動追従はしない。

`lock` はGLB・動作設定・参照モーションを固定する。`sync` は全参照とハッシュを検証してからGLBと動作JSONを出力する。動作JSONはAsset Hubの形式で、GLBだけを他のエンジンへ渡しても連続回転や照明設定は付いていかない。利用側は設定を実装するか、制作側でGLBへ焼き付ける。

GLBの仕様検証、動作の構造検証、見た目の確認は別の検査である。骨格の直接互換は、服の干渉、足滑り、道具の接触、ゲームでの使用適合まで保証しない。
